# agents-monitor 設計書

- 作成日: 2026-10-09
- 状態: 実装済み
- 仮称: agents-monitor

## 1. 目的

複数の Claude Code セッションを並行で動かしていると、どのセッションがユーザーの入力を待っているかを見落とす。agents-monitor は、マシン上で動いている Claude Code セッションの状態をメニューバー（タスクトレイ）に常時一覧表示し、対応が必要なセッションを見落とさないようにする。

### 対象ユーザー

Claude Code を使うすべての人。特定個人向けではなく、配布して誰でも導入できることを前提とする。

### 成功の基準

- 「要対応」「エラー停止」になったセッションに、エディタやターミナルを見ていなくても気づける
- 設定ディレクトリ（`CLAUDE_CONFIG_DIR`）の違いに関係なく、マシン上のセッションが 1 つの一覧にまとまる
- 導入時のユーザー操作が「アプリを入れる → セッションを開き直す」で済む（`~/.claude` 以外の設定を使う人は、設定画面でフォルダーを選ぶ）
- Claude Code の動作を妨げない（遅くしない、出力を汚さない、失敗させない）

### 対象範囲

| 区分 | 内容 |
|---|---|
| 対応 OS | macOS から始める。Windows / Linux に広げられる構成にする |
| 対応する起動元 | ターミナルの `claude`、VS Code 拡張 |
| 後回し | Claude デスクトップアプリの Code タブ（必要になれば追加） |
| 対象外 | claude.ai/code（クラウド実行）、コンテナ内・SSH 先で動くセッション（イベントが手元に届かないため） |

## 2. 全体構成

3 つの部品で構成する。リポジトリは 1 つにまとめ、そのリポジトリ自体を Claude Code プラグインのマーケットプレイスとしても使う。

```
Claude Code セッション（複数・プロフィール問わず）
  └─ agents-monitor プラグインの hooks
       └─ agents-monitor-hook（アプリ同梱の小さなプログラム）
            └─ 1 イベント = 1 ファイルで書き出し ─▶ ~/.agents-monitor/events/
                                                        │ 監視・読み取り後に削除
メニューバーアプリ（Tauri） ◀──────────────────────────────┘
```

### 2.1 プラグイン（hooks だけを持つ）

- 必要な hook イベントを登録し、すべて `agents-monitor-hook` を呼ぶだけにする
- 状態の判断ロジックは持たない（壊れにくく、更新頻度を下げるため）
- `agents-monitor-hook` が存在しない場合は何もせず正常終了する

### 2.2 agents-monitor-hook（Rust 製の小さな実行ファイル）

アプリのインストール時（および更新時）に `~/.agents-monitor/bin/` へ配置する。

役割:

1. 標準入力から hook の JSON を受け取る
2. 必要な項目だけを取り出す（5 章）。長い文字列は切り詰め、生の `tool_input` は保存しない
3. 親プロセスをたどって Claude 本体のプロセス ID を特定する（hook はシェル経由で起動されることがあり、直接の親が Claude とは限らないため）
4. `SessionStart` のときだけ、画面移動用の端末情報を環境変数から集める（7.3 節）
5. 一時ファイルに書き、リネームで `~/.agents-monitor/events/` に置く（途中まで書かれたファイルを読ませないため）

守ること:

- 何が起きても終了コード 0 で終わる
- 標準出力に何も出さない（`SessionStart` や `UserPromptSubmit` では標準出力が Claude のコンテキストに入るため）
- 起動から終了までを短時間に収める（目標は 1 回あたり数十ミリ秒以内。実装時に計測する）
- `~/.agents-monitor/` は本人だけが読み書きできる権限（0700）で作る

### 2.3 メニューバーアプリ（Tauri）

| 部品 | 役割 |
|---|---|
| イベント読み取り | `events/` を監視し、届いたファイルを時刻順に読んで削除する |
| セッション管理 | イベントから各セッションの状態を決める（4 章） |
| プロセス監視 | 数秒ごとに Claude のプロセスを確認し、消えたセッションを「終了」にする。hook が届いていない Claude プロセスは「状態不明」として出す |
| プラグイン導入 | 設定ディレクトリを探し、同意に基づいて `claude plugin install` を実行する（8 章） |
| 通知 | 設定された状態になったときに OS 通知を出す |
| 表示 | メニューバーのアイコンと、アイコン下に出す一覧ウィンドウ（6 章） |
| 画面移動 | 該当するターミナルのタブや VS Code のウィンドウを前面に出す（7.3 節） |
| 設定の保存 | 並び順・通知設定・設定ディレクトリ一覧などを保存する |

一覧は OS 標準のメニューではなく、Web 技術で描画する小さなウィンドウとして実装する（ドラッグでの並び替え、行の背景色、経過時間表示のため）。

### 2.4 HTTP 送信を採らない理由

hook からアプリへ HTTP で直接送る方式は、アプリが起動していないとイベントが失われる。ファイル書き出し方式なら、アプリの起動前に起きたことも起動後に復元できる。

## 3. 状態の種類

ユーザーに見せる状態は 5 つ。内部ではより細かい状態を持ち、補足として表示する。

| 表示 | 色 | 内部の状態 |
|---|---|---|
| 要対応 | 黄 | 許可待ち、質問待ち、プランの承認待ち（表示は「承認待ち」）、MCP からの入力要求 |
| エラー停止 | 赤 | API エラー、利用上限など（`error_type` を補足に表示） |
| 完了 | 青 | 応答完了（次の指示待ち）、中断後の待ち、開始直後（「新規」）。バックグラウンド作業が残っている場合は補足に「バックグラウンド作業あり」 |
| 実行中 | 緑 | 実行中（補足に実行中のツールと対象）、サブエージェント実行中、コンテキスト圧縮中 |
| 終了 | （表示しない） | 正常終了、プロセス消滅。一覧には出さない。遅れて届くイベントを捨てるため、内部では 5 分間だけ記録を残す |
| 状態不明 | グレー（枠線のみ） | Claude プロセスはあるが hook が届いていない（補足に起動元と「監視対象外」、詳細に理由と対処を表示。一覧の Unknown タブに分けて出す） |

急ぐ順は「要対応 > エラー停止 > 完了 > 実行中 > 終了・状態不明」とする。

## 4. 状態の決め方

### 4.1 基本方針

- 状態遷移は「今の状態 + イベント → 次の状態」という純粋な関数として実装する
- イベントと状態の対応表はコード内の 1 か所にまとめ、後から変更しやすくする
- 知らないイベント・知らない項目は無視する（Claude Code の更新で壊れないため）
- `agent_id` を持つイベント（サブエージェント内のイベント）は本体の状態を変えない。サブエージェントの開始・終了だけを本体の補足に反映する

### 4.2 対応表（初期版）

| イベント | 次の状態 | 補足 |
|---|---|---|
| `SessionStart` | 完了 | 「新規」 |
| `UserPromptSubmit` | 実行中 | |
| `PreToolUse` | 実行中 | 「Bash: npm test」「Edit: src/app.ts」のように表示 |
| `PreToolUse`（`AskUserQuestion`） | 要対応 | 質問待ち |
| `PreToolUse`（`ExitPlanMode`） | 要対応 | 承認待ち |
| `PermissionRequest` | 要対応 | 許可待ち（対象のツールと内容） |
| `Notification`（`permission_prompt`） | 要対応 | 許可待ち |
| `Notification`（`elicitation_dialog`、`elicitation_url_dialog`、`agent_needs_input`）、`Elicitation` | 要対応 | 入力要求 |
| `PostToolUse`、`PostToolUseFailure`、`ElicitationResult` | 実行中 | 許可・回答の後に再開したとみなす |
| `SubagentStart` | 実行中 | 「サブエージェント実行中」 |
| `SubagentStop` | （変えない） | 動いているサブエージェントから外す。残っていれば `Stop` で「バックグラウンド作業あり」 |
| `PreCompact` | 実行中 | 「圧縮中」 |
| `Stop`、`Notification`（`idle_prompt`） | 完了 | |
| `StopFailure` | エラー停止 | `error_type`（`rate_limit` など） |
| `SessionEnd` | 終了 | |
| （プロセス消滅を検知） | 終了 | |

### 4.3 実装の最初に確かめること

- Esc で中断したときに届くイベント。`Stop` が届かない場合は、一定時間イベントがない実行中セッションについて、会話ログ（`transcript_path`）の末尾に中断の記録があるかを確認して「完了」にする
- 許可待ちで `PermissionRequest` と `Notification(permission_prompt)` がどの順で届くか
- バックグラウンド作業が残っているときに届くイベント
- hook を非同期で実行するオプションの有無と、hook が Claude Code の応答に与える遅延

結果に応じて 4.2 の表を調整する。

## 5. イベントファイルの形式

1 イベント = 1 JSON ファイル。ファイル名は `<ts_ms を 13 桁ゼロ埋め>-<hook のプロセスID>-<ナノ秒>.json`（名前順＝時刻順になる）。

```json
{
  "schema": 1,
  "ts_ms": 1791541441123,
  "event": "PreToolUse",
  "session_id": "…",
  "agent_id": null,
  "claude_pid": 12345,
  "config_dir": "/Users/foo/.claude-personal",
  "cwd": "/Users/foo/Projects/my-api",
  "transcript_path": "…",
  "detail": {
    "tool_name": "Bash",
    "summary": "npm test",
    "notification_type": null,
    "error_type": null
  },
  "terminal": null,
  "git_branch": null
}
```

- `schema` は形式のバージョン。アプリは知らないバージョンの項目を無視する
- `config_dir` は `CLAUDE_CONFIG_DIR`、未設定なら `~/.claude`
- `summary` はツールの種類ごとに作る短い説明（コマンド、ファイルパスなど）。最大 120 文字で切り詰める
- `ts_ms` は UNIX エポックからのミリ秒（並べ替えを単純にし、日付ライブラリを不要にするため）
- `terminal` と `git_branch` は `SessionStart` のときだけ入れる（7.3 節）
- `git_branch` は `cwd` の `.git/HEAD` から読む（git コマンドを起動しない）

## 6. 画面

### 6.1 メニューバーのアイコン

- 一目で「自分が対応すべきものがあるか」「作業中のものがあるか」がわかることを目的とし、件数は出さない
- アイコンは食パンの形（Figma の `MenuBarIcon`）。状態があるときは右下に丸囲みの記号を表示する
  - 要対応: `!`
  - エラー停止: `×`
  - 実行中: `▶`
  - それ以外（完了・状態不明だけ、またはセッションなし）: 記号なし
- 記号は 1 つだけ出し、要対応 → エラー停止 → 実行中の順に優先する
- 色は付けず、テンプレート画像として macOS に白と黒の切り替えを任せる（明るいメニューバーでも見えるようにするため）
- 記号の有無で横幅を変えない（左隣のアイコンがずれないようにするため）

### 6.2 一覧ウィンドウ

アイコンをクリックするとアイコンの下に開く。見た目は Figma の `AgentMenu` に合わせる。

- 角丸と枠線のある板。ウィンドウを透明にし、高さは中身に合わせる。行が多いときは一覧の中をスクロールする
- 配色は OS の外観設定（ライト・ダーク）に合わせて切り替える
- 上部に「Agents」「Unknown」のタブと、右端に ≡。開くたびに Agents タブに戻る
  - Agents: 状態不明以外のセッション
  - Unknown: 状態不明のセッション
  - ≡: 設定（9 章）
- 各行の表示: 状態の色の点、プロジェクト名（`cwd` の末尾）、補足、その状態になってからの経過時間（右端。実行中・要対応・エラー停止のときだけ）
- 補足は「状態の詳細 - ブランチ名」。詳細がなければ状態名を出す。状態不明は「監視対象外 - 起動元」
- 同じプロジェクトのセッションが複数あるときだけ、ブランチ名（worktree 名）を添えて区別する

### 6.3 並び順

- 状態によって並びを変えない
- 初めて見るプロジェクトは末尾に追加する（起動順）
- ドラッグ＆ドロップで並び替えられる。並び順はセッション ID で保存し、再開したセッションは元の位置に戻る（詳細は v0.2 設計書の 6 章）
- 新しいセッションは、同じプロジェクトのセッションがあればその後ろに並べる
- 並び順はアプリの設定として保存し、アプリの再起動後も保つ

### 6.4 行の操作

- 行を押すと、そのセッションの画面へ移動する。移動できない環境や移動に失敗したときは、行の詳細（`cwd` のフルパス、プロフィール）を開く。メッセージは出さない
- 詳細は、行の右端のボタンで開け閉めする
- 詳細は v0.3 設計書の 3.2 節

## 7. 通知と画面移動

### 7.1 通知

- 初期設定では、要対応・エラー停止になったときに通知する。どの状態で通知するかは設定で変えられる
- 文面の例: タイトル「my-api — 許可待ち」、本文「Bash: rm -rf dist」
- 同じセッションが同じ状態のままなら繰り返し通知しない
- 通知のクリックで、該当セッションへ移動する（できなければ一覧を開く）

### 7.2 初回起動時の通知許可

起動時に OS の通知許可を求める。許可されなかった・オフになっているときは、設定アイコンのバッジで誘導する（v0.2 設計書 5 章）。

### 7.3 画面移動

`SessionStart` 時に、hook が次の情報を `terminal` に記録する:
`TERM_PROGRAM`、`ITERM_SESSION_ID`、`TMUX` / `TMUX_PANE`、`CLAUDE_CODE_ENTRYPOINT`（ターミナル・VS Code 拡張などの起動元）、TTY。

- VS Code 系のエディターでは、そのプロジェクトのウィンドウを前面に出す（会話のタブは選ばない。理由は v0.3 設計書 2.1 節）
- ターミナルは、そのアプリを前面に出すだけにする（タブは選ばない）
- tmux の中のセッションは対象外
- 詳細は v0.3 設計書

## 8. プラグインの導入

### 8.1 監視の対象の設定ディレクトリ

- 初めての起動で `~/.claude` があれば対象にする
- それ以外のディレクトリは、ユーザーが設定画面でフォルダーを選んで追加する。自動では探さない

### 8.2 導入

- 対象のディレクトリに対して `CLAUDE_CONFIG_DIR` を切り替えながら、アプリに同梱したマーケットプレイス（`~/.agents-monitor/marketplace` に写したもの）の登録とプラグインのインストールを `claude` CLI で実行する
- 初めての起動の `~/.claude` だけは黙って入れる。ほかは追加したときに入れる
- 設定画面から削除すると、プラグインを外して対象から消す
- 詳細は v0.2 設計書の 2〜4 章

設定ファイル（`settings.json`）を直接書き換えることはしない。

### 8.3 以降の動作

- アプリの更新で同梱プラグインの版が上がったら、対象のディレクトリのプラグインも更新する
- インストールに失敗したディレクトリ（組織の管理設定で禁止されている場合など）は、理由を表示して自動では再試行しない

### 8.4 `claude` コマンドの場所

GUI アプリにはターミナルの PATH が引き継がれないため、`~/.local/bin`、`/opt/homebrew/bin`、`/usr/local/bin`、npm のグローバル領域を順に探す。見つからなければ設定で指定してもらう。

## 9. 設定

別ウィンドウにはせず、一覧ウィンドウの ≡ で開く。

- 通知する状態の選択（要対応・エラー停止・完了。初期値: 要対応、エラー停止）
- アプリの終了
- 監視の対象の設定ディレクトリの一覧（追加・削除・プラグインの導入状況）
- `claude` コマンドの場所
- ログイン時に起動するか

## 10. プロセス監視

- 数秒ごとに Claude のプロセス一覧を取得する
- イベントで知っている `claude_pid` が消えていれば、そのセッションを「終了」にする
- イベントが届いていない Claude プロセスは「状態不明」とする。ただし次は除外する:
  - `claude -p` などの非対話実行
  - `claude plugin …` などのサブコマンド実行（アプリ自身の実行を含む）
- VS Code 拡張内で動く Claude のプロセスの見え方は実装時に確認し、除外条件を調整する

## 11. エラー処理

| 場面 | 対処 |
|---|---|
| hook 内の失敗全般 | 終了コード 0 で終わり、何も出力しない |
| `agents-monitor-hook` が無い | プラグイン側のコマンドで存在を確認し、無ければ何もしない |
| 読めないイベントファイル | 読み飛ばして削除し、ログに残す |
| 知らないイベント・項目・`schema` | 無視する |
| アプリが起動していない間のイベント | `events/` に残り、起動時にまとめて読む。極端に溜まった場合は古いものから捨てる |
| アプリのクラッシュ | 再起動時に、残っているイベントファイルと保存済みの状態から一覧を復元する |
| プラグイン導入の失敗 | 理由を表示してスキップする |
| `claude` コマンドが見つからない | 設定で場所を指定してもらう |

## 12. テスト

- **状態遷移**: 純粋な関数として、実際のセッションで記録したイベント列をテストデータにしてユニットテストを書く
- **agents-monitor-hook**: 標準出力に何も出さないこと、書き込めない場合も終了コード 0 で終わること、所要時間、秘密情報になりうる生データを書き出さないことを自動テストで確認する
- **結合テスト**: 一時的な設定ディレクトリにプラグインを入れ、`claude -p` を動かして、想定どおりのイベントファイルが届くことを確かめる
- **手動確認**: 4.3 節の確認項目、画面（アイコン・一覧・並び替え・通知・初回セットアップ）の確認リスト

## 13. 配布

（v0.5 で改めた。詳しくは `2026-10-12-agent-loaf-v0.5-distribution-design.md`）

- macOS アプリは Apple の Developer ID で署名し、公証する（Apple Developer Program への登録が必要）
- 配布は GitHub の Releases の `.dmg`。Homebrew は対象外（使う人が増えてから検討する）
- Apple Silicon の Mac だけ、macOS 14 以降
- 自動更新は、新しい版を知らせて、押したら更新して再起動する。1 日に 1 回確かめる。更新の後の起動で hook も新しくなる
- プラグインはアプリに同梱して入れる。同じリポジトリをマーケットプレイスとしても使える。将来は公式マーケットプレイスへの掲載を目指す
