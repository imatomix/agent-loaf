# 0003. 軽さを仕様の条件にする

- ステータス: 承認
- 日付: 2026-10-11

## コンテキスト

Agent Loaf は常に動くメニューバーのアプリ。2026-10-11 に測ると、何もしていないのに CPU が約 3% だった。1 秒ごとの画面の描き直しと、3 秒ごとの `ps` が原因だった。

## 決定

- 定期的な処理・外部コマンドの起動・画面の描き直しを足すときは、負荷を見積もり、できれば測る
- 何もしていないときは CPU 0.1% 前後を目安にする
- 重くなる案は、軽い代わりの案と並べて示し、選んでもらう

2026-10-11 に行った対策の例:

- 一覧を閉じている間は画面を描き直さない
- `ps`・`lsof` をやめ、libc の `proc_*`・`sysctl` で読む
- hook は全プロセスではなく自分の親だけをたどる
- `claude` を起動するプラグインの状態の確認は、設定の画面を開いたときだけ
- 一覧を閉じている間は、知っている pid が生きているかだけを確かめる

結果、何もしていないときの CPU は約 0.2% になった。

（追記 2026-10-13）メモリーを減らすため 2026-10-12 に入れた「一覧を閉じるたびに画面を捨てる」作りは、開くのが数秒遅くなる場面があったため取りやめた（ADR 0009）。

## 検討した代替案

- **kqueue・FSEvents でイベントを待つ**: 1 秒ごとの置き場の読み込みがなくなり、さらに下がる。まだ行っていない

## 影響

新しい機能の設計書には、増える処理と負荷の見積もりを書く。
