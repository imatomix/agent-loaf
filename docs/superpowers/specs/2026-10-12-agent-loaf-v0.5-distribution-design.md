# Agent Loaf v0.5（配布と公開）設計書

- 作成日: 2026-10-12
- 状態: レビュー待ち
- 元の設計書: `2026-10-09-agents-monitor-design.md` の 13 章（配布）。この文書は 13 章を具体化し、一部を改める
- 前提: v0.4（`2026-10-11-agents-monitor-v0.4-design.md`）と、アプリ名の変更（agents-monitor → Agent Loaf）が済んでいること

## 1. 目的

ほかの人が GitHub からダウンロードして、警告なしに開け、通知がすぐ届き、新しい版をアプリの中から入れられるようにする。そのうえで、リポジトリを GitHub に公開する。

### 成功の基準

- Releases からダウンロードした dmg のアプリが、Gatekeeper の警告なしに開く
- 初めて起動したときに、macOS が通知の許可を尋ねる
- 新しい版を出すと、遅くとも 1 日でアプリの設定の画面に知らせが出て、押すと更新して再起動する。更新の後も通知の許可が残っている
- タグを push するだけで、署名・公証済みの dmg と更新の情報が Releases の下書きに上がる
- 公開したリポジトリに、パスワード・鍵・トークン・メールアドレスが入っていない

### 対象外

- Homebrew（自分の tap も公式の Cask も）。使う人が増えてから検討する
- Intel の Mac。手元で確かめられないため。声があれば universal にする
- macOS 以外への対応。Codex への対応は v0.5.0 に含める（`2026-10-12-agent-loaf-codex-design.md`）
- v0.4 の見直しで残した小さい指摘 6 件（1・3・4・5・8・10 番）。公開の後に回す

### 決めたこと（2026-10-12、ユーザーと）

| 項目 | 決めたこと |
|---|---|
| 署名 | Apple Developer Program に登録し、Developer ID で署名・公証する（個人での登録。決めた時点では未登録） |
| 作る場所 | GitHub Actions（`tauri-action`）。最初の 1 回だけ手元で署名と公証を通して設定を確かめる |
| 自動更新 | 新しい版を知らせ、押したら更新して再起動する。勝手に入れ替えない |
| 確かめる頻度 | 起動の約 1 分後に 1 回、その後は 24 時間ごと |
| 対応する Mac | Apple Silicon だけ |
| 対応する macOS | 14（Sonoma）以降。確かめたのは 26 |
| 公開するもの | リポジトリ全体（`docs/superpowers/` と履歴も） |
| 最初の公開の版 | v0.5.0 |
| ≡ のバッジ | 新しい版があっても付けない（バッジは「確認が必要な問題」の意味のため） |

## 2. 公開の流れ

### 2.1 一度だけの準備（ユーザーが行う）

1. Apple Developer Program に登録し、Developer ID Application の証明書を作って、この Mac のキーチェーンに入れる
2. 公証のための App 用パスワードを作る
3. 自動更新の署名の鍵を作る（`npx tauri signer generate`）。公開鍵は `tauri.conf.json` に書き、秘密鍵は自分だけが持つ
4. 秘密鍵とそのパスワード、Developer ID の証明書（`.p12`）とそのパスワードを、パスワード管理のアプリなどにも控える（5 章）
5. 手元で署名から公証までを 1 回通す（`docs/releasing.md` の手順）
6. 確かめた値を GitHub の Secrets に入れる

### 2.2 公開のたびに

1. 版の番号を上げてコミットし、`v0.5.0` のようなタグを push する
2. GitHub Actions が次を行う
   - Apple Silicon 用の hook を作って同梱する（`scripts/build-hook-sidecar.sh`）
   - アプリを作り、Developer ID で署名し、公証する
   - dmg と、自動更新のための `.app.tar.gz`・その署名・`latest.json` を作る
   - Releases に**下書き**として上げる
3. ユーザーが中身を確かめてから「公開」を押す

下書きにするのは、壊れた版が利用者に届かないようにするため。自動更新は、公開された版の `latest.json` だけを見る（`https://github.com/imatomix/agent-loaf/releases/latest/download/latest.json`）。

### 2.3 GitHub Actions

- ワークフローは `.github/workflows/release.yml` の 1 つ。`v*` のタグの push でだけ動く
- 実行環境は GitHub の macOS（Apple Silicon）。公開のリポジトリなので無料
- `tauri-action` を使い、`releaseDraft: true`、`args: --target aarch64-apple-darwin`
- Secrets: `APPLE_CERTIFICATE`（`.p12` を base64）、`APPLE_CERTIFICATE_PASSWORD`、`APPLE_SIGNING_IDENTITY`、`APPLE_ID`、`APPLE_PASSWORD`（App 用パスワード）、`APPLE_TEAM_ID`、`TAURI_SIGNING_PRIVATE_KEY`、`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`
- ほかの人の Pull Request からは動かない（タグの push だけ）ので、Secrets は読まれない

### 2.4 アプリの設定

- `tauri.conf.json`
  - `bundle.macOS.signingIdentity` は `"-"`（ad-hoc）のまま残し、手元の開発のビルドは今までどおり作れるようにする。公開のビルド（CI と手元での確かめ）では、環境変数 `APPLE_SIGNING_IDENTITY` で Developer ID を渡して上書きする（上書きできることは実装の最初に確かめる）
  - `bundle.macOS.minimumSystemVersion: "14.0"`
  - `bundle.createUpdaterArtifacts: true`
  - `plugins.updater.pubkey` と `endpoints`
- 版の番号は 0.5.0 にそろえる（今のテストで確かめる）

## 3. アプリの中の自動更新

### 3.1 確かめるとき

- 起動の約 1 分後に 1 回、その後は 24 時間ごとに 1 回、`latest.json` を読む
- 読むのは小さなファイル 1 つだけで、負荷はほぼない
- 確かめられなかったとき（オフラインなど）は何も表示せず、30 分後にもう一度確かめる（スリープから戻った直後は Wi-Fi がまだつながらず失敗しやすく、次を 24 時間後にすると何日も知らせが出ないことがあるため。見直しで決定）
- 確かめる処理とダウンロードには 10 分の制限をかける（通信が止まって固まらないように）
- 確かめるのは、公開のビルドだけにする。公開の手順（CI と手元での確かめ）で、作るときに環境変数 `AGENT_LOAF_RELEASE=1` を渡し、アプリはそれを作るときに読み込んで（`option_env!`）、あるときだけ確かめる。`tauri dev` や手元の開発のビルドでは確かめない

### 3.2 状態

Rust の側で持つ。状態の移り変わりは core の純粋な関数にし、アプリはそれを呼ぶだけにする（今の作りと同じ分け方）。

| 状態 | 意味 | 設定の画面 |
|---|---|---|
| なし | 最新、またはまだ確かめていない | 「アップデート」の欄を出さない |
| ある（版） | 新しい版がある | 「新しいバージョン {new} があります（今は {current}）」と「アップデートして再起動」 |
| ダウンロード中（%） | ダウンロードと入れ替えの途中 | 「ダウンロードしています… {percent}%」。押せるものはない |
| 失敗 | ダウンロード・入れ替え・署名の確認のどれかに失敗した | 「アップデートできませんでした。ネットワークにつながっているか確かめてください。」と「もう一度」（replay のアイコン付き） |

- 状態が変わると画面に知らせる。一覧は開くたびに作り直すので、画面は開いたときに今の状態を受け取る
- 見た目は Figma の「v0.5 下書き（アップデート）」（`150:1053`）。「Claude Code の設定」と「ログイン時に起動する」の間に置く
- ≡ のバッジは付けない

### 3.3 更新するとき

- 「アップデートして再起動」を押すと、ダウンロードしながら進み具合を出し、署名の鍵で中身を確かめてから入れ替え、`app.restart()` で再起動する
- 再起動すると、同梱の hook は起動したときの写し直しで、プラグインは版が変わったときの更新（v0.2）で新しくなる
- 再起動の間の数秒は監視が止まる。状態は保存しているので、再起動の後も続く

### 3.4 ライブラリ

- `tauri-plugin-updater` を 1 つ足す（ユーザーと確認済み）。再起動は Tauri 本体の `app.restart()` を使い、`tauri-plugin-process` は足さない

## 4. GitHub への公開

### 4.1 公開する前の点検

- 今のファイルと Git の履歴の全部について、パスワード・鍵・トークン・個人の情報を `git grep` と `git log -p` で探す（新しい道具は入れない）。見つかったら、公開する前にユーザーと相談する
- コミットのメールアドレスは、すでにすべて GitHub の noreply（`3133649+imatomix@users.noreply.github.com`）になっている（2026-10-12 に確認）。公開されるのは作者の名前だけ

### 4.2 手順

1. ユーザーが `gh` を `imatomix` のアカウントに切り替える
2. `imatomix/agent-loaf` を公開のリポジトリとして作り、push する。説明文とトピックを付ける
3. 2 章の流れで v0.5.0 を作り、Releases に公開する

### 4.3 文書

- README（日本語・英語）
  - 「入手」を、Releases から dmg をダウンロードして「アプリケーション」に入れる手順にする。ソースからの作り方は「開発」に移す
  - 「必要な環境」を「Apple Silicon の Mac、macOS 14 以降（確かめたのは macOS 26）」にする
  - 「設定」にアップデートの欄を足す
  - 「保存するデータ」の近くに、外との通信として「1 日に 1 回、GitHub に新しい版を確かめに行く。ほかには通信しない」を書く
- `docs/releasing.md`（新規）: 一度だけの準備、手元での確かめ方、公開のたびの手順、鍵の控え
- `.claude-plugin/marketplace.json` は残す（アプリに同梱して入れるのが基本。リポジトリから手で入れることもできる）

## 5. 失敗したとき・鍵の扱い

| 場面 | 扱い |
|---|---|
| CI で作る・署名・公証のどこかが失敗した | Releases には何も上がらない。直してから同じタグを付け直す |
| 公証が Apple の側で通らない | ログの理由を見て直す。最初に手元で通すので、ここで初めて分かることは少ない見込み |
| 更新の確認に失敗した | 何も出さず、次の回に確かめる |
| ダウンロード・入れ替えに失敗した | 「失敗」を出し、「もう一度」で試し直せる。入れ替える前の失敗なら、今の版のまま動く |
| 署名が合わない更新が届いた | 入れ替えない。「失敗」と同じ表示 |

- 自動更新の秘密鍵をなくすと、配ったアプリに更新を届けられなくなる（利用者に手で入れ直してもらうしかない）。秘密鍵・パスワード・証明書は GitHub の Secrets のほかにも控える（2.1 の 4）

## 6. テスト

- **core のユニットテスト**
  - 更新の状態の移り変わり（なし → ある → ダウンロード中 → 失敗 → もう一度、失敗のときは今の版のまま）
  - 次に確かめる時刻の計算（起動の 1 分後、その後 24 時間ごと、スリープから戻ったときに過ぎていればすぐ）
- **設定のテスト**: 版の番号がそろっていること（今のテスト）に、`plugins.updater.pubkey` と `endpoints` があること、`minimumSystemVersion` が 14.0 であることを足す
- **実機での確認**
  - 署名と公証を通したアプリを、ダウンロードした形（quarantine の印付き）で開き、警告が出ないこと
  - 初めて起動したときに通知の許可を尋ねること
  - v0.5.0 を入れた状態から、試しの版（v0.5.1）を Releases に上げ、設定の画面に知らせが出て、更新して再起動でき、通知の許可が残っていること。試しの版は確かめた後に消す
  - オフラインで起動しても、何も表示されず動き続けること

## 7. 実装の順番

Apple の登録の審査を待つ間に、署名なしでできるものを先に進める。

1. 自動更新の仕組み（3 章）と画面。手元では ad-hoc のまま、確かめる処理を止めた状態で作る
2. `tauri.conf.json` の設定、GitHub Actions のワークフロー、`docs/releasing.md`、README
3. 公開する前の点検（4.1）
4. 登録が済んだら: 2.1 の準備 → 手元で署名と公証 → Secrets → リポジトリの公開 → v0.5.0 のタグ → 実機での確認
