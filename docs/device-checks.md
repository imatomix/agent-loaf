# 実機で確かめる場面

Agent Loaf の価値は、対応が必要な会話を正しく知らせることにある。テストでは確かめきれない、Claude Code・Codex と画面の組み合わせを、決まった手順で実機で確かめる。

## いつ通すか

- 公開の前（すべて）
- Claude Code や Codex の版が上がった後（その組み合わせだけ）
- 状態の決め方、hook、画面の移動を変えた後（関係する場面だけ）

結果は、下の「記録」に版と日付をつけて残す（ADR 0008）。

## 組み合わせ

| 記号 | エージェント | 画面 |
|---|---|---|
| CT | Claude Code | ターミナル（Terminal.app・Ghostty・iTerm2 のどれか。使ったものを書く） |
| CV | Claude Code | VS Code の拡張 |
| XV | Codex | VS Code の拡張 |
| XT | Codex | ターミナル（`--no-daemon`） |

## 場面

通知の設定は、要対応・エラー停止・完了をすべてオンにしておく。

| # | 操作 | 期待すること | CT | CV | XV | XT |
|---|---|---|---|---|---|---|
| 1 | 会話を始めて、最初の依頼を送る | 一覧に行が出て「実行中」になる | ○ | ○ | ○ | ○ |
| 2 | 許可が要る操作を頼む（例: `curl` で何か取ってくる） | 「要対応」になり、通知が出る | ○ | ○ | ○ | ○ |
| 3 | 許可して続けさせる | 「実行中」に戻る | ○ | ○ | ○ | ○ |
| 4 | 応答が終わるまで待つ | 「完了」になり、通知が出る | ○ | ○ | ○ | ○ |
| 5 | 応答の途中で止める（Esc や停止のボタン） | 「完了（中断）」になる（Claude Code は約 15 秒後） | ○ | ○ | ○ | ○ |
| 6 | 一覧の行を押す | その会話の画面が前に出る | ○ | ○ | ○ | ○ |
| 7 | 通知を押す | その会話の画面が前に出る | ○ | ○ | ○ | ○ |
| 8 | 「要対応」のまま会話を閉じる（ターミナルは終了、VS Code はウィンドウを閉じる） | 一覧から消える（「要対応」のまま残らない） | ○ | ○ | ○ | ○ |
| 9 | 同じウィンドウで、何も送らずに新しいチャットを 2 回始める | 「新規」の行は 1 つだけ |  | ○ | ○ |  |
| 10 | 「完了」の行を一覧で見て、そのまま 1 時間置く | 一覧に出なくなる。その会話にまた送ると戻る | ○ | ○ | ○ | ○ |
| 11 | Mac をスリープさせ、数時間後に戻ってから一覧を開く | 一覧がすぐ開き、状態が正しい | ○ | ○ | ○ | ○ |
| 12 | アプリを終了して起動し直す | 動いている会話が、正しい状態で一覧に戻る | ○ | ○ | ○ | ○ |
| 13 | 前の日などの通知が通知センターに残っている会話に、また送る | 終わったときに通知が出る。その会話の古い通知は消え、新しい 1 つだけが残る | ○ | ○ | ○ | ○ |
| 14 | 行をつかんで上下に動かし、離す（詳細を開いた行でも） | ほかの行がずれて、落とす位置にすきまが空く。離すとその位置に入り、ちらつかない | ○ | ○ | ○ | ○ |

空欄は、その組み合わせでは起きない場面。
