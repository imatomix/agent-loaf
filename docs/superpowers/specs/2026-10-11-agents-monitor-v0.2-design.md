# agents-monitor v0.2 設計書

- 作成日: 2026-10-11
- 状態: 実装済み
- 元の設計書: `2026-10-09-agents-monitor-design.md`（この文書は、その 6.3・7.2・8・9 章を v0.2 として具体化し、一部を改める）

## 1. 目的

v0.1 では、プラグインをターミナルから手で入れる必要があった。v0.2 では次の 2 つを実現する。

- 導入時の操作を「アプリを入れる → セッションを開き直す」で済ませる。起動時にユーザーへ何かを選ばせることはしない
- 一覧の並び順をドラッグで変えられ、開き直したセッションも元の位置に戻る

### 成功の基準

- `~/.claude` を使う人は、アプリを起動するだけでプラグインが入る
- それ以外の設定ディレクトリを使う人は、設定画面でフォルダーを選ぶだけでプラグインを入れられ、要らなくなれば外せる
- アプリを更新すると、入れたプラグインも同じ版になる
- 監視できていない・通知が届かないなど、ユーザーが手を打つべき状態に、設定アイコンのバッジで気づける

### 対象外

- `~/.claude-*` などの設定ディレクトリを自動で探すこと。ユーザーがフォルダーを選んで追加する
- 初回セットアップ画面
- 画面移動（v0.3）、署名・公証・自動アップデート（配布の段階）

## 2. 流れ

| 場面 | 動き |
|---|---|
| 初めての起動 | `~/.claude` があれば監視の対象に加え、プラグインが入っていなければ黙って入れる。ほかのディレクトリには触らない |
| `~/.claude` がない | 起動時に一覧ウィンドウを開いて設定画面を表示し、「Claude Code の設定」に「Claude Code の設定ディレクトリが見つかりません」と出す。ここから追加できる |
| 追加 | 「追加」からフォルダーを選ぶと、監視の対象に加えてプラグインを入れる |
| 削除 | プラグインを外し（`plugin uninstall`）、同梱版のマーケットプレイスを登録していればその登録も外して（`marketplace remove`）、監視の対象から消す。`~/.claude` を削除した場合も、次の起動で入れ直さない |
| アプリの更新 | 監視の対象のうち、入っている同梱プラグインの版が古いディレクトリを更新する |
| 通知 | 起動時に通知の許可を求める（OS が出す許可の画面は、アプリが求めないと出ないため）。断られた・オフになっている場合はバッジで誘導する |

「Claude Code の設定」の一覧は、そのまま監視の対象を表す。一覧（Agents タブ）・メニューバーのアイコン・通知は、監視の対象の設定ディレクトリで動いているセッションだけを扱う。削除したディレクトリのセッションは、hook がイベントを送り続けていても（Claude Code はプラグインを外しても、動いているセッションでは読み込み済みの hook を使い続ける）その場で表示から消える。追加すれば、そのディレクトリで動いているセッションはすぐに表示される。パスは末尾の `/` を除き、実在すればシンボリックリンクを実体に直してから照らす。状態不明の行（プロセスだけが見えている行）はどの設定のものか見分けられないので、これまでどおり Unknown タブに出す。

入れたあとも、すでに動いているセッションは監視されない。これは Unknown タブに「状態不明」として出て、その説明（プラグインを入れてから会話を開き直すと監視される）で案内する。入れたことを通知では知らせない。

## 3. 全体構成

判断は core クレートの純粋な関数、`claude` の実行と画面はアプリに分ける。v0.1 の「状態遷移は core、監視ループはアプリ」と同じ分け方で、判断はユニットテストで確かめる。

| 置き場所 | 役割 |
|---|---|
| core `plugin_status` | `claude plugin list --json` と `claude plugin marketplace list --json` の出力から、ディレクトリごとの導入状態を判定する |
| core `install_plan` | 導入状態と同梱プラグインの版から、次に実行すること（入れる・更新する・何もしない）を決める |
| core `config_dirs` | 監視の対象の初期値（`~/.claude` があるか）を決める |
| core `order` | 並べ方と `session_order` の更新 |
| core `claude_cli` | `claude` コマンドの場所を探す |
| アプリ `installer` | 同梱マーケットプレイスの配置、`claude` の実行（裏の 1 スレッドで順に）、結果を画面へ送る |
| アプリ `notifier` | 通知の許可状態を調べ、許可を求める（v0.1 の `notifier.rs` に足す） |
| 画面 | 設定画面の「Claude Code の設定」、設定アイコンのバッジ、ドラッグでの並び替え |

### 3.1 同梱プラグインの配置

- `.app` に、マーケットプレイス一式（`.claude-plugin/marketplace.json` と `plugin/`）を同梱する
- アプリの起動時に、これを `~/.agents-monitor/marketplace/` へ写す。hook の実行ファイルと同じく、中身が変わったときだけ写し直す
- ディレクトリごとに、`~/.agents-monitor/marketplace` を `agents-monitor` という名前のマーケットプレイスとして登録し、`agents-monitor@agents-monitor` を入れる
- `.app` の中を直接登録しないのは、アプリを別の場所へ動かすと登録先が壊れるため

### 3.2 `claude` の呼び出し

ディレクトリごとに環境変数 `CLAUDE_CONFIG_DIR` を設定して実行する。

| 目的 | コマンド |
|---|---|
| 状態を読む | `claude plugin list --json`、`claude plugin marketplace list --json` |
| 入れる | `claude plugin marketplace add ~/.agents-monitor/marketplace`、`claude plugin install agents-monitor@agents-monitor` |
| 更新する | `claude plugin update agents-monitor@agents-monitor`（`marketplace update` は要らない。`notes/2026-10-11-v0.2-cli-findings.md`） |
| 外す | `claude plugin uninstall agents-monitor@agents-monitor`、`claude plugin marketplace remove agents-monitor` |

- 呼び出しは裏の 1 スレッドで 1 件ずつ行い、重ねない
- 1 件 60 秒で打ち切る
- GUI アプリには PATH が引き継がれないので、見つけた `claude` のあるディレクトリを PATH の先頭に足して渡す
- アプリが呼ぶ `claude plugin …` は、v0.1 のプロセス監視ですでに「状態不明」から除いている
- 状態は、起動時・追加や削除の後・設定画面を開いたときに読み直す。定期的には読まない

### 3.3 `claude` の場所

元の設計書 8.4 節のとおり、`~/.local/bin`、`/opt/homebrew/bin`、`/usr/local/bin`、npm のグローバル領域を順に探す。アプリの設定に `claude_path` があればそれを優先する。どれでも見つからなければ、設定画面で場所を入力してもらう。

## 4. 導入の状態

監視の対象のディレクトリごとに、次のどれかに判定する。画面では状態の文字は出さず、行の右のアイコンで示す（Figma「v0.2 下書き/修正案」）。

| 状態 | 判定 | 行のアイコン |
|---|---|---|
| 入っている | `agents-monitor@agents-monitor` が入っていて有効。どのマーケットプレイスから入ったか（同梱版・GitHub・開発中のフォルダー）は問わない | 削除 |
| 入っていない | 入っていない、または無効にされている。CLI で外された場合や、入れるのに失敗した場合を含む | もう一度・削除 |
| フォルダーがない | 追加したフォルダーがなくなった | 削除（監視の対象から消すだけ） |

- 別の場所から入っているものも、イベントは届いて監視できるので「入っている」と同じに扱う。同じ名前のマーケットプレイスがあって同梱版は登録できないので、追加したときは何もせずに対象に加える
- 「削除」は、入っている元に関係なくプラグインを外してから、監視の対象から消す（2 章）。同梱版のマーケットプレイスを登録していた場合は、その登録も外す
- アプリの更新時に更新するのは、同梱版のマーケットプレイスから入れたものだけ。別の場所から入れたものは、その元で更新される
- 「もう一度」は、入っていなければ入れ、無効なら有効にする（`claude plugin enable`）
- 起動時に自動で入れるのは、初めての起動の `~/.claude` だけ
- `claude` を実行している間は、その行のアイコンを押せなくする
- CLI の出力の読み方は、2026-10-10 に `claude` 2.1.296 で取った実際の出力をテストデータにする

### 4.1 失敗の知らせ方

| 失敗した場面 | 知らせ方 |
|---|---|
| 「追加」「もう一度」「削除」を押した | macOS 標準のアラートで理由を出す（エラー出力の最後の行、200 字まで） |
| 初めての起動で `~/.claude` に入れたとき、アプリの更新でプラグインを更新したとき | ユーザーが操作していないのでアラートは出さない。設定アイコンのバッジと、行の「もう一度」で知らせる。「もう一度」で失敗すればアラートで理由を出す |

失敗の理由は保存しない。

## 5. 画面

画面の見た目は Figma（ファイルのキーは非公開）の「v0.2 下書き/修正案」で決める。ここには載せる内容だけを書く。

### 5.1 通知設定

- 通知が許可されていない・オフのとき、通知設定のいちばん上に「通知がオフになっています」と、システム設定を開く歯車アイコンを出す
- 歯車アイコンには、ツールチップとボタンの名前（`aria-label`）として「システム設定を開く」を付ける

### 5.2 設定画面の「Claude Code の設定」

通知設定の下に足す。

- 監視の対象のディレクトリを並べ、それぞれに 4 章のアイコンを出す。アイコンにもツールチップとボタンの名前（「もう一度」「削除」）を付ける
- 中央に「＋ 設定ディレクトリを追加」。macOS 標準のフォルダーを選ぶ画面を開き、選んだディレクトリを監視の対象に加えて入れる。すでに対象にあるディレクトリは足さない
- 対象が 1 つもないときは「Claude Code の設定ディレクトリが見つかりませんでした。使用している設定ディレクトリを追加してください。」と出す
- `claude` が見つからないときは、場所の入力欄を出す

フォルダーを選ぶ画面とアラートには、Tauri 公式の `tauri-plugin-dialog` を使う（2026-10-11 に導入の了承を得た）。

### 5.3 設定アイコンのバッジ

タブの設定アイコン（≡）に、次のどれかのときバッジを付ける。設定画面の該当する箇所を見れば、何をすればよいかわかるようにする。

- 通知が許可されていない・オフ
- 入っているディレクトリが 1 つもない
- `claude` が見つからない
- 入っていないディレクトリがある

## 6. 並び替え

### 6.1 並べ方

並び順はセッション ID で覚える。会話を `--resume` や `--continue`、VS Code 拡張の履歴から再開してもセッション ID は変わらない（2026-10-11 に `claude` 2.1.296 で確認）ので、再開したセッションは元の位置に戻る。

- アプリの設定の `session_order`（セッション ID の並び）の順に並べる
- `session_order` にない新しいセッションは、同じ `cwd` のセッションが並んでいればその最後のすぐ後ろに、なければ末尾に入れ、その時点で `session_order` にも加える。ふだんは同じプロジェクトが隣り合う
- 状態不明のセッション（イベントが届いておらずセッション ID がわからない）は末尾に置き、並び替えの対象にしない
- 終了したセッションの ID も、後で再開されたときのために残す。500 件を超えたら、表示していないものを並びの先頭側から消す（いつ加えたかは覚えないので、古さではなく位置で決める。500 件あれば実用上は困らない）

並べ方は core `order` の純粋な関数にし、`session_views` から使う。

### 6.2 操作

- 行をつかんでドラッグし、1 行ずつ動かす。同じプロジェクトの別のセッションは一緒に動かない
- 落とす位置に線を出す
- HTML の標準のドラッグ＆ドロップではなく、マウスの動きを自分で追う。WKWebView では標準のドラッグの見た目を細かく変えにくいため
- 行を押すと詳細を開く今の操作と区別するため、一定の距離（4px）を動かしたらドラッグとみなす
- 離したときに新しい並びをアプリへ送り、`session_order` を保存する

## 7. 保存するデータ

アプリの設定（`~/.agents-monitor/settings.json`）に次を足す。Claude Code の設定ファイル（`~/.claude/settings.json` など）には触らない。

| 項目 | 初期値 | 用途 |
|---|---|---|
| `config_dirs` | なし（まだ決めていない） | 監視の対象の設定ディレクトリ |
| `claude_path` | なし | `claude` を自動で見つけられないときに指定する |
| `session_order` | 空 | 並び順（セッション ID の並び） |

- `config_dirs` が「なし」のときだけ、起動時に `~/.claude` を探す。あれば `["~/.claude"]` にして入れる。なければ「なし」のままにし、次の起動でもう一度探す
- 一度でも値が入れば、以後は `config_dirs` のとおりに扱う。空の一覧（すべて削除した状態）と「なし」は区別するので、`~/.claude` を削除しても入れ直さない
- v0.1 の設定ファイルは項目が足りないまま読めるようにする（`serde(default)`）

## 8. エラー処理

| 場面 | 対処 |
|---|---|
| `claude` が見つからない | 設定画面で場所を入力してもらい、バッジを付ける |
| `claude plugin …` が失敗した（組織の管理設定で禁止されている場合など） | そのディレクトリは「入っていない」のまま。4.1 節のとおりに知らせ、ほかのディレクトリは続ける |
| `claude` が 60 秒以内に終わらない | 打ち切り、理由を「時間切れ」として失敗と同じに扱う |
| CLI の JSON が読めない（版の違いで形が変わった場合など） | そのディレクトリを「入っていない」とし、理由を「導入状態を読めませんでした」として失敗と同じに扱う |
| 同梱マーケットプレイスを写せない | 入れる操作をすべて失敗として扱い、4.1 節のとおりに知らせる |
| 追加したフォルダーが消えた | 「フォルダーがない」とし、削除のアイコンだけを出す |
| 通知が許可されていない・オフ | 通知設定のいちばん上に案内を出し、バッジを付ける |

## 9. テスト

- **core のユニットテスト**
  - CLI の JSON の読み方（実際の出力をテストデータにする）
  - 導入状態の判定（4 章の 3 状態。別の場所から入っているもの・無効にされたものを含む）と、次に実行することの決め方（版の変化、同梱版かどうかを含む）
  - `config_dirs` の初期値（「なし」で `~/.claude` がある・ない、空の一覧のとき）
  - 並べ方（新しいセッションを同じ `cwd` の後ろに入れる、状態不明は末尾）と `session_order` の上限
  - v0.1 の設定ファイルを読めること
- **結合テスト**（`scripts/integration-test.sh`、手動で動かす）
  - 一時的な設定ディレクトリと一時的な `AGENTS_MONITOR_HOME` を作り、core の手順でプラグインを入れて、`claude plugin list --json` で導入済みになることを確かめる。続けて外し、未導入に戻ることを確かめる
  - `claude -p` を 1 回動かし、一時的なイベント置き場にイベントファイルが届くことを確かめる
  - 新しい設定ディレクトリにはログイン情報がないので、`ANTHROPIC_API_KEY` か `CLAUDE_CODE_OAUTH_TOKEN` が環境にあるときだけ `claude -p` を動かし、なければ理由を出して導入の確認だけで終わる
  - 普段の `cargo test` からは外す（本物の `claude` と API を使い、環境に左右されるため）
- **手動確認**
  - 新しいユーザーのつもりで（`~/.agents-monitor` と `~/.claude` のプラグインを外してから）起動し、`~/.claude` に入ること
  - `~/.claude` がない環境（`HOME` を一時的なディレクトリにして起動）で、設定画面が開いて案内が出ること
  - 追加・削除・もう一度、失敗したときのアラート、`~/.claude` を削除した後の再起動
  - 通知がオフのときのバッジと案内
  - ドラッグでの並び替えと、再起動後もその順が保たれること
  - 同梱プラグインの版を上げてアプリを作り直し、更新されること

## 10. 実装の最初に確かめること

- フォルダーから入れたプラグインで、`~/.agents-monitor/marketplace` の中身を書き換えたときに、`marketplace update` と `update` が要るか、写し直すだけで反映されるか（`plugin list --json` に `readFromFolder` という項目がある）
- `claude plugin install` を `CLAUDE_CONFIG_DIR` だけ変えて実行したときに、ほかの設定ディレクトリに影響しないこと
- `plugin uninstall` と `marketplace remove` で、設定ディレクトリにプラグインの痕跡が残らないこと
- 初回の通知の許可を求めたときに、許可の画面が出るか。2026-10-10 の確認では画面が出ずにシステム設定でオフになっていたため、ad-hoc 署名のアプリで起きることか、前の仕組み（`NSUserNotificationCenter`）で送ろうとした影響かを確かめる
- 一覧ウィンドウ（ほかを押すと閉じる）から、フォルダーを選ぶ画面やシステム設定を開いたときの閉じ方
- 別の場所から入っているディレクトリで `plugin uninstall` したときに、そのマーケットプレイスの登録が残ること（残すのが正しい。ユーザーが自分で登録したものなので）

結果に応じて 3.2・4・5 章を調整する。
